# Сценарий записи демо-видео (до 20 минут)

Раскадровка для записи экрана: что открыть, что нажать, что должно быть видно и сколько
это длится. Порядок блоков совпадает с требованиями организаторов, поэтому видео можно
сверять с ними один к одному.

**Перед записью** (2 минуты, не в кадре):

```bash
cd <корень репозитория>          # там, куда склонирован репозиторий
./scripts/demo.sh                      # поднимет всё и напечатает адрес
./scripts/verify.sh                    # убедиться: 2002 / 289533 / 502 / 385, ALL SEGMENT FIELDS MATCH
```

Открыть два окна браузера: обычное (вход `analyst`) и приватное (для блока 6 — `analyst2`).
Разрешение — не меньше 1600×900, чтобы таблицы читались. Масштаб браузера 100 %.

> Если расчёт на вашей машине быстрее, чем успеваете говорить, — **не добавляйте
> задержек**. Покажите сохранённый журнал с реальными отметками времени и скажите об этом.

## Блок 9 · Архитектура и решения (18:00 – 20:00)

Говорить по одному тезису на пункт, без слайдов:

1. **Стек:** NiceGUI + PostgreSQL + отдельный воркер. Почему: команда на Python, одна
   кодовая база без фронтенд-сборки, очередь и состояние в одной БД. Альтернативы
   (React/Go, Celery/Redis, Docker) отвергнуты осознанно — [`docs/DECISIONS.md`](DECISIONS.md).
2. **Три слоя хранения:** вертикальная витрина (одна строка = атрибут в срезе) →
   производное сравнение → факты counts с привязкой к заявкам. Почему: сумма ячеек не
   равна числу заявок, и переход «число → заявка» должен быть точным.
3. **Процедуры как данные:** формат ответа знает только пользовательская процедура;
   ядро — универсальный обход. Поэтому приложение принимает JSON, XML и любой другой
   формат, добавленный новой процедурой. Эквивалентность разбора проверена на всех
   2002 парах: 572 221 строка, 0 расхождений.
4. **Измерения:** полный цикл ~84 с на свободной машине (расчёт 19 с, загрузка в
   PostgreSQL ~39 с). Узкое место — загрузка ~1.4 млн строк, а не вычисления: запись
   `rows.jsonl` — половина стадии нормализации. `VACUUM` вернул сводную с 7.3 с к 0.88 с —
   на этой машине латентность чтения определяется физическим состоянием таблиц.
   Все числа с условиями замера — [`docs/BENCHMARKS.md`](BENCHMARKS.md).
5. **Ограничения, прямо:** GPU не измерен (Python 3.14 + 4 ГБ VRAM), инкрементальной
   загрузки нет (пункт задания помечен «не обязательно»), установка проверялась на этой
   машине, масштаб 20 000 заявок не запускался.
