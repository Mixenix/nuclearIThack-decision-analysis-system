# Журнал состязательных проверок

Здесь записано, что именно пытались сломать, чем это закончилось и что осталось
непроверенным. Цель — не «мы молодцы», а воспроизводимость: каждый пункт можно
перепроверить командой.

---

## 1. Входные форматы (JSON / XML / свой ридер)

**Что атаковали.** Расширения в разном регистре, смешанный набор файлов, несколько масок,
маска с `..` и абсолютным путём, дубли APP_ID, namespace в XML, mixed content, числа
вида `007` и `1e3`, BOM, cp1251, UTF-16, пустой файл, два корня, DOCTYPE с сущностями.

**Результат:**

| Атака | Итог |
|---|---|
| `*.json` при файлах `.XML` | понятная ошибка, **добавлена подсказка** с реально найденными расширениями |
| `../*.json`, `/etc/*.json`, пустая маска | `InvalidRequest` — обход пути закрыт |
| дубль APP_ID (`I1.json` + `I1.xml`) | ошибка с обоими путями |
| namespace `{urn:x}a` попадал в `PATH` | **исправлено**: имена приводятся к локальным |
| mixed content | `ValueError` с предложением своего ридера |
| cp1251 без объявления / два корня / мусор | понятная ошибка разбора |
| cp1251 и UTF-16 **с объявлением** | разбираются корректно |
| «billion laughs» (8 уровней сущностей) | блокируется лимитом Python 3.14, память не растёт |

**Независимая проверка эквивалентности** (свой кодировщик JSON→XML, не код агента):
4004 документа, **572 221 строка, 0 расхождений** между JSON- и XML-разбором.

**Не проверено:** XML на 20 000 заявок; экзотические кодировки (EBCDIC, Shift-JIS);
смешанный датасет «часть пар в JSON, часть в XML» (маска поддерживает, прогон — нет).

## 2. Числа и семантика

| Проверка | Результат |
|---|---|
| Пустая выборка (`app_ids=[]`) | везде 0, без падений и деления на ноль |
| Фильтр, не совпадающий ни с чем | 0, отчёт открывается |
| `decision_changed=false` + `diff_flag=1` | **117** (502 − 385) — сходится с ручным счётом |
| Ячейка сводной против drill-down | число в ячейке = размер множества заявок (26/26 автопроверок) |
| CNT=273 против APP_IDS=20 | в UI и HTML подписано «примеры, всего найдено 273» — не выдаётся за полный список |
| Четыре типа изменения | `SAME 275121 / VALUE_CHANGED 7567 / ATTRIBUTE_NEW 3835 / ATTRIBUTE_LOST 3010` — совпадает со `STATUS.md` |

## 3. Документация против кода

Написан `tools/check_doc_claims.py`: он читает истину из базы и из сборки тестов и
сверяет **16 конкретных утверждений** в README/CONTRIBUTING/STATUS/BENCHMARKS/
ARCHITECTURE_NOTE, а также ищет устаревшие фрагменты (старый счёт тестов, удалённые
`run_id`, прежний адрес машины). Инструмент включён в `scripts/verify.sh`.

Им найдено и исправлено:
* `README` утверждал «171 passed» — устарело, стало 280;
* `CONTRIBUTING` писал «2002 пары» без разряда — приведено к общему формату;
* `ARCHITECTURE_NOTE` утверждал «pandas нужен для соединений», хотя `pandas` в проекте
  **не импортируется вообще** — заменено на фактическое «чистый Python + SQL»;
* `DECISIONS` содержал старый IP машины.

Он же поймал бы любое будущее расхождение — это и есть смысл проверки.

## 4. Безопасность

| Атака | Результат |
|---|---|
| Проверка с `LABEL = '"><script>alert("xss")</script><img src=x onerror=...>'` | в HTML всё экранировано: `&lt;script&gt;`, `&#34;`; сырых тегов нет |
| Техническая ошибка в проверке (мой же баг `NameError: run`) | записана как `ERROR`, а не бизнес-`FAIL` — как требует контракт |
| Список проверок строится импортом пользовательского файла | **исправлено ранее**: `CHECK` читается через `ast`, без исполнения в веб-процессе |
| Путь вне `DATASET_ROOT` | `InvalidRequest` (проверено `../` и абсолютным путём) |
| Чужой прогон по прямому URL | `AccessDenied` во всех сервисах; проверено и пробником, и браузером |

**Не проверено:** исполнение заведомо вредоносного кода (в модели доверия хакатона это
вне объёма), ограничения по памяти на стадии сравнения для датасета 20 000 заявок.

## 5. Тесты

Проверено, что в наборе нет «мнимых» проверок: у файлов в `tests/` есть содержательные
ассерты, а ручные браузерные сценарии без ассертов **вынесены** из `tests/e2e` в
`tools/dev/playwright/` — иначе они создавали ложное впечатление покрытия.

Итог: **280 тестов** (unit 195 / интеграционные 66 / e2e 19), все зелёные; отдельно —
24 HTTP-проверки живого приложения и браузерный обход всех экранов.

---

## 6. Что осталось непроверенным (честно)

1. GPU-режим (нет RAPIDS под Python 3.14 и 4 ГБ VRAM) — осознанно вне объёма.
2. Масштаб 20 000 заявок: не запускался.
3. Установка на второй машине с другой ОС.
4. Холодный кэш: все замеры чтения — на прогретых страницах, кроме специально
   оговорённого случая «первая сводка после прогона».
5. Отчёт при **упавшем** `CHECKS_ONLY` (должен ли показывать последнюю опубликованную
   ревизию) — поведение есть, тестом не закреплено.
