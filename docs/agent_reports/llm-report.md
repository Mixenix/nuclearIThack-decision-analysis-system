# Отчёт агента: блок «Альтернативное мнение ИИ», HTML-экспорт, страница отчёта проверок

Роль:
`reports/llm` (teammate `llm-report`): независимое второе мнение на DeepSeek,
автономный HTML-экспорт отчёта, страница отчёта проверок в UI.

参与的需求 Rxx：
- **R12** — отчёт проверок по ссылке и скачиваемый HTML, из которого можно провалиться в приложение;
- **R19** — независимое мнение LLM рядом с проверками (реальный ответ или честное «недоступно»);
- частично **R14** — вызов модели не блокирует event loop (кнопка в UI идёт через `run.io_bound`);
- частично **R16** — детерминированная сводка в HTML (считает `reports/summary.py`, рендер мой).

## 实现了什么

### 1. `src/change_analysis/llm/adapter.py` — реальная интеграция, а не заглушка

- `status() -> {available, provider, model, timeout_sec, reason}` — проверка конфигурации **без сетевого запроса**:
  пустой `LLM_PROVIDER` / `LLM_API_KEY_ENV` / незаданная переменная с ключом /
  не-абсолютный `LLM_BASE_URL` ⇒ `available=False` и текстуальная причина.
  Ключ читается только по имени переменной из настроек (`os.environ[settings.llm_api_key_env]`);
  в коде, в payload и в сохранённом результате ключа нет (проверено тестами).
- `build_payload(run_id, revision, extra=None)` — ограниченный детерминированный пакет:
  мета прогона, лёгкая сводка (`summary_light`), конфигурация **без исходного кода**
  (только `source_kind`/`source_ref`/`params`, пути обрезаны до имени файла),
  топ‑15 изменяемых `PATH`, до 40 строк проверок, `flips_by_cause`, 6 примеров
  смены решения, выборка различий с `evidence_id` (`E1…En`), словарь полей,
  ограничения и ожидаемая схема ответа. `extra` (аргумент `payload` из контракта)
  трактуется как *дополнительный контекст*: очищается, обрезается до 2 000 символов
  и уходит в `extra_context`, расширить пакет им нельзя.
- Выборка evidence — **стратифицированная** и детерминированная: `row_number() OVER
  (PARTITION BY path)` по топ‑15 путям, `ORDER BY apps DESC, path, app_id, array_key`,
  поэтому одни и те же данные всегда дают одни и те же `E1…En`. Лимит `LLM_MAX_EVIDENCE`
  (по умолчанию 40, потолок 200).
- `_trim()` — жёсткий бюджет `LLM_MAX_PAYLOAD_CHARS` (24 000): сначала режется выборка,
  затем частые атрибуты, затем строки проверок; всё урезанное отражается в `trim_notes`.
- `_redact()` — маскирует `sk-…`, `Bearer …`, `password/secret/token/api_key=…` во всех
  строках пакета (`[скрыто]`).
- `_validate_response()` — ответ обязан быть JSON‑объектом; поддерживаются
  `summary`, `observations[{text, evidence_id}]`, `uncertainty`, `next_steps`;
  наблюдение, ссылающееся на `evidence_id`, которого **не было в отправленном пакете**,
  отбрасывается и считается (`dropped_evidence`). Лимиты: 20 наблюдений, 10+10 пунктов.
- `request_second_opinion(run_id, revision, payload)` — полный цикл с честными состояниями:
  - нет ключа/провайдера ⇒ `UNAVAILABLE` + причина, **HTTP не выполняется вообще** (тест это фиксирует);
  - ошибка сборки пакета ⇒ `ERROR`, `stage=build_payload`;
  - HTTP ≠ 200 ⇒ `ERROR` с `http_status` и обрезанным телом ответа;
  - таймаут/сеть ⇒ `ERROR` с типом исключения;
  - `finish_reason=length` ⇒ `ERROR` «ответ модели обрезан по max_tokens», а не «битый JSON»;
  - успех ⇒ `DONE` + `latency_ms`, `usage`, `response_model`, `payload_hash`, `evidence`.
- `_persist()` — **append-only** `INSERT` в `ca.llm_reports`
  (`run_id, revision, provider, model, payload_hash, state, result, error, finished_at`).
  Никаких `DELETE`/`TRUNCATE`/`UPDATE` из моего кода.
- `load_report(run_id, revision)` — отдаёт **последний успешный** ответ; если более поздняя
  попытка была неуспешной, возвращает `last_attempt {state, error, at}`, чтобы UI и HTML
  могли написать: «показан более ранний успешный ответ, последняя попытка — ошибка».

### 2. `templates/report.html.j2` + `reports/export.py` — автономный HTML

- Один `<style>` inline, **ноль** внешних ресурсов: нет `<script>`, `<link>`, `@import`,
  `url(http…)`, `src=`, CDN и шрифтов. Документ читается локально (`file://`) без сервера.
- Все значения идут через autoescape Jinja2 + `markupsafe.escape`; пользовательские
  `LABEL`, `ARGUMENT`, имена, JSON‑значения и **текст модели** экранируются.
  Идентификатор заявки не превращается в ссылку, если он не вида `I32554362`
  (`is_safe_app_id`).
- Ссылки обратно в приложение только абсолютные, от `PUBLIC_BASE_URL`:
  страница прогона, отчёт проверок, сводная таблица (и список заявок в ней), карточки заявок.
- Добавлен блок **«Независимое мнение ИИ»** с тремя честными состояниями:
  ответ модели (сводка, наблюдения со **строкой evidence** рядом — приложение, PATH,
  ARRAY_KEY, до/после, ссылка на заявку), «Чего не хватает», «Что предлагает проверить»,
  провайдер/модель/фактически ответившая модель/задержка/токены/отпечаток пакета и
  дисклеймер «это текст модели, а не проверка, числа не меняются»;
  либо «Мнение ИИ недоступно. Состояние: ERROR/UNAVAILABLE + причина»;
  либо «Мнение ИИ не запрашивалось» + причина ненастроенной интеграции.
- Добавлен блок **«Конфигурация прогона»**: датасет, срезы, backend, процедуры
  (`source_kind`/имя файла), проверки и их параметры, технические исключения —
  с пометкой, что исходный код в отчёт не попадает.
- Проверки: HIGH FAIL — ярко (красный фон, жирный вердикт), LOW FAIL — бледно **и словами**
  («FAIL · низкая уверенность (слабый сигнал)»), техническая ошибка исполнения — отдельным
  блоком, не как бизнес‑FAIL.

### 3. `ui/pages_report.py` — страница отчёта проверок

- Кнопка **«Независимое мнение ИИ»** запускает реальный запрос через
  `background.io_bound(...)` (поток, event loop свободен), кнопка блокируется,
  показывается «запрос к модели выполняется…», результат зависит от состояния
  (`positive` / `warning` / `negative`), затем блок перерисовывается.
- Блок показывает: бейдж состояния, провайдер/модель, фактически ответившую модель,
  задержку, время запроса, отпечаток пакета, сводку, наблюдения с evidence и ссылкой на
  карточку заявки, «Чего не хватает», «Что предлагает проверить», счётчик отброшенных
  ссылок, заметку о неуспешной последней попытке и дисклеймер.
- Обработчик защищён от ухода пользователя со страницы (`is_deleted`), чтобы фон не падал.
- Строки проверок: HIGH FAIL — `bg-red-100 / border-red-500`, вердикт красный полужирный;
  LOW FAIL — `bg-amber-50/40 / border-amber-200`, текст «FAIL · низкая уверенность»;
  технические ERROR — отдельный оранжевый блок с `check_id` и текстом ошибки.

## 使用/修改了哪些接口

Соблюдены контракты `docs/CONTRACTS.md` §7 без изменения смысла:

- `status() -> dict` — как в контракте; **добавлен** ключ `timeout_sec` (аддитивно).
- `request_second_opinion(run_id, revision, payload) -> dict` — подпись та же; `payload`
  документирован как «дополнительный контекст», а не «тело запроса» (безопаснее: пакет
  всегда строит адаптер и он всегда ограничен).
- `export_report(run_id, out_path, base_url) -> str` — без изменений; атомарная запись
  `tmp → replace` сохранена.
- `render_report(...)` — добавлены **опциональные** `llm`, `llm_status`, `configuration`
  (по умолчанию `None`), старые вызовы работают как раньше.
- Новые публичные имена в `llm/`: `build_payload`, `config_digest`, `load_report`,
  константы `MAX_*`, `MAX_RESPONSE_TOKENS`. Новый фильтр Jinja: `json_inline`, `safe_app_id`.
- Чтение: `ca.runs`, `ca.comparison_rows`, `ca.app_segments`, `ca.check_results` /
  `ca.check_executions` (только SELECT, в т.ч. через `services.checks.build_check_report`).
  Запись: **только** `ca.llm_reports` (`INSERT`), append-only.
- Новая переменная окружения `LLM_MAX_EVIDENCE` (по умолчанию 40, потолок 200).
  Она читается из `os.environ`, потому что в `config.Settings` нет поля; `load_settings()`
  и так копирует `.env` в `os.environ`, поэтому значение из `app/.env` подхватывается.
  **Просьба владельцу `config.py`/`.env.example`:** добавить `LLM_MAX_EVIDENCE=40`
  в `.env.example` и, если хочется, поле в `Settings` — тогда уберу чтение env.

## 什么没有验证及原因

1. ~~Живой процесс на :8000 был старее моих правок~~ — **снято**: после перезапуска
   в 11:54:51 живое приложение проверено по HTTP браузером (см. таблицу выше):
   страница, клик по кнопке, скачивание HTML — всё прошло на реальном процессе.
   Повторного перезапуска для сдачи не требуется.
2. **LOW‑confidence FAIL на реальных данных** не показан: в прогоне 818573ab все 32 строки —
   31 `FAIL/HIGH` и 1 `PASS/HIGH`, LOW‑строк нет. Бледный вариант проверен подстановкой
   строки в UI и юнит‑тестом, но не «живым» LOW на этом датасете.
3. **Путь через очередь** (`worker/runner.py::run_llm_job`) end-to-end не прогонял:
   это файл лида, и для него нужен поставленный LLM‑джоб. Адаптер, который он вызывает,
   покрыт тестами; сам `run_llm_job` перед вставкой делает `DELETE FROM ca.llm_reports
   WHERE run_id/revision` — то есть **не append-only**; я об этом предупредил лида
   (можно убрать `DELETE`, тогда история сохранится).
4. **Ретраи/бэкофф** не реализованы: одна попытка на клик, любая ошибка честно
   записывается. Это сознательно — для демо важнее показать истинное состояние.
5. **Текстовые утверждения модели не проверяются машинно** (кроме существования
   `evidence_id`). Мы намеренно не делаем вид, что проверяем смысл: рядом с каждым
   наблюдением печатается строка evidence, чтобы несовпадение видел аналитик
   (например, модель иногда ссылается на E‑строку другого атрибута — это видно глазами).
6. **Стоимость/латентность** измерены на одном прогоне (20.6–22.6 КБ пакета,
   7.0–7.8 тыс. prompt‑токенов, 6.6–8.9 с). Серия из 10 вызовов для средних значений

## 假设与限制

- **Ключ** живёт только в `app/.env` и читается через имя переменной из настроек;
  ни код, ни payload, ни `llm_reports.result` его не содержат (тесты это фиксируют).
- **Пакет для модели** не содержит: исходного кода процедур/проверок, `DATABASE_URL`,
  токенов сессий, паролей, полной витрины. Содержит: агрегаты, атрибуты‑агрегаты,
  строки проверок, детерминированную выборку различий (id заявки + PATH +
  значение до/после), словарь полей и ограничения.
- **Детерминированные числа не меняются**: результат модели хранится отдельно
  (`ca.llm_reports`) и в HTML/UI выводится отдельным блоком с дисклеймером.
- `ca.llm_reports` **растёт**: каждый клик добавляет строку с полным результатом
  (~8–20 КБ). Показан последний успешный ответ; неуспешная последняя попытка
  раскрывается отдельной пометкой. Чистки нет намеренно (не моя зона, и это история).
- Пороговые значения: `LLM_MAX_PAYLOAD_CHARS=24000`, `LLM_MAX_EVIDENCE=40` (потолок 200),
  `MAX_RESPONSE_TOKENS=2000`, `MAX_OBSERVATIONS=20`, timeout 60 с.
