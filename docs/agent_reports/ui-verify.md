# Browser verification and fixes — 2026-11-07

## Method and scope

Used **Python Playwright 1.64.1 with real system Chromium `/usr/bin/chromium`**, headless, 1440×1000. Clicked rendered controls, filled inputs and CodeMirror, followed application links, downloaded files and opened the downloaded HTML with `file://`. No injected application/authentication state. The first account signed in through the login form; subsequent drivers reused its browser cookies. `analyst2` signed in in a fresh, independent context without copied cookies.

The CUA browser host was unavailable. The initial pip mirror failed DNS; PyPI installation succeeded. Playwright's Chromium CDN returned geographic HTTP 403, so the installed system Chromium was used. No NiceGUI synthetic-user or HTTP-only substitute was needed.

Read CONTRACTS.md, the UI modules/main.py, and PLAN.md §§14.3, 15, 16.3, 21.4. Product edits were confined to `src/change_analysis/ui/`; harnesses and this report are in the allowed paths. No services, database code, worker, reports, templates, task package, or `.env` was edited. Other ongoing work changed some files/data during verification; those changes were preserved.

Server: port **8091** only. For the final checks the launch environment was:

```sh
APP_PORT=8091 PUBLIC_BASE_URL=http://127.0.0.1:8091 LLM_PROVIDER= LLM_API_KEY_ENV= PYTHONPATH=src .venv/bin/python main.py
```

The existing `.env` initially advertised another public port and an available DeepSeek integration. I did not pretend that configuration was unavailable: the first browser pass displayed the configured provider. I explicitly disabled the optional LLM in this test server's launch environment to exercise the required unavailable state. No paid/model request was clicked. Public URL was explicitly set to 8091 for export. Ports 8080/8090 were never killed.

I started one worker to process the UI-created run, then stopped **that worker** with SIGINT; it exited with code 0. Other workers/processes were not killed. The UI-created run eventually completed. The web server remains available on 8091.

## Fixes made in the allowed UI layer

- `pages_runs.py`: explicitly serialize the Quasar row-click row ID before the Python callback. Also localized the pagination label.
- `pages_config.py`: tolerate absent precheck detail fields on error; keep the saved configuration ID and replace the URL so refresh reloads it and repeated save updates it; validate JSON objects at save time instead of silently discarding malformed input; retain one status label.
- `pages_run.py`: use `run_stages()` for complete stage records including IDs/code references; stop confusing the worker's row counter with processed application pairs; use an indeterminate global progress bar during running; translate stage names and DONE/PENDING labels through the layout.
- `layout.py`: read the report contract's uppercase `METRIC`; add Russian stage-state labels.
- `pages_explore.py`: pass list options to NiceGUI (tuple previously caused a visible 500); obtain the complete product list through the service; recompute on dimension changes; move pivot/drill service calls to background threads; serialize matrix recomputations; bind drill to the filters used to build the displayed matrix rather than unsaved filter edits; handle a layout with no dimensions as one total cell.
- `pages_workspace.py`: preserve the saved procedure ID in the URL and show save status; reject malformed/non-object params; replace web-process import/exec validation with AST parsing and an explicitly limited syntax/declaration message. Actual import/contract execution remains the worker's responsibility.
- `pages_report.py`: move HTML export off the event-loop thread and display progress/error feedback; show the current unavailable LLM configuration even if a historical opinion exists, identifying that opinion as historical. Other concurrent report/LLM changes were preserved, not claimed as this task's implementation.
- `tests/e2e/ui_*.py`, `tests/e2e/README.md`: rerunnable real-browser drivers, step logs, downloads, screenshots, exact drill membership and independent contexts. `compileall` passed for the UI and drivers. The individual scenarios were run during this task; the later convenience `ui_suite.py` wrapper was not itself run as a single uninterrupted suite.

## Remaining failures / coordinator decisions

**P1 — checks-only revision hides the analytical facts.** After workspace execution the run's revision advanced from 1 to 2 (then 3 for the deliberate technical failure). Opening that run's explore page showed an empty sample despite 2002 processed applications. Browser reproduction: `c455dbfb-2239-428e-83a8-fd114b4222fb`, run a workspace check, click «Сводная таблица». `services/runs.py::request_checks_only` increments `runs.revision`; `services/report.py::pivot`, `drill`, `apps_page` restrict facts to that latest revision. The pipeline facts still belong to revision 1. This is outside the allowed write scope. Coordinator must choose a stable data revision separate from check revision, or an equivalent service-level compatibility fix. Do not hide this with fake counts in the UI.

**P1 — report loses earlier check results after another checks-only job.** The custom LOW FAIL row was visible at revision 2. After the deliberate technical failure at revision 3 the report showed only the technical block and zero business rows. `services/checks.py::build_check_report` selects exactly the current revision; the worker executes only the added checks. Thus the table is merged within one revision, but does not retain all checks across additions. Coordinator must define and implement the expected cumulative/latest-per-check behavior (including HTML export). I did not change service revision semantics in the browser layer.

**Configuration decisions.** The real `.env` and stored historical LLM results changed during other work. The test server intentionally overrides LLM availability and export origin. Before demo deployment, coordinator must set the intended `PUBLIC_BASE_URL` and decide whether LLM is enabled; the UI must continue to report that real state. Some seeded dataset references temporarily disappeared/changed during testing; the early raw-JSON failure was recorded, then successfully repeated after that external correction.

**Presentation limits still present.** Raw worker log messages remain in their original English; the UI shell/controls are Russian. Stage progress counters are the worker's last emitted counts and may stop short of the total even when the stage is DONE. High-cardinality pivot layouts truncate displayed rows; only the exercised default, CLASS×SOURCE and empty-dimension layouts are claimed here. These are not claims of complete coverage of PLAN.md.
