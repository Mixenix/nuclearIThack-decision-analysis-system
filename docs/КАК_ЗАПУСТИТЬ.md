# Как запустить и что показывать

**Graeae** · команда «Бойцовский клуб» · Сафин Амир Ильясович, Мальцев Даниил Игоревич

Короткая инструкция на 1 страницу: три команды до работающего приложения, затем
9 шагов демонстрации с ожидаемыми числами. Подробный 20-минутный сценарий с репликами —
в [`DEMO.md`](DEMO.md); здесь только то, что нужно в момент показа.

---

## 1. Запуск (60 секунд)

```bash
cd <корень репозитория>          # там, куда склонирован репозиторий
./scripts/demo.sh
```

Скрипт поднимает PostgreSQL, применяет миграции, создаёт демо-пользователей и датасет,
запускает веб-приложение и отдельный worker, затем печатает адрес. Например:

```
Готово. Открывайте:
  http://192.168.0.27:8000
  вход: analyst / analyst   (второй пользователь: analyst2 / analyst2)
```

Адрес определяется автоматически: при смене сети (дом, вуз, площадка) он подстроится сам,
переписывать конфигурацию не нужно. Остановить всё — `./scripts/demo.sh --stop`.

Если приложение уже запущено вручную (`./scripts/web.sh` и `./scripts/worker.sh`), скрипт
ничего не сломает: он переиспользует работающие процессы.

**Важно:** после любой правки кода приложение нужно перезапустить — autoreload выключен,
иначе страница продолжит отдавать старый код из памяти.

## 2. Что открыть

| Адрес | Что там |
|---|---|
| `/login` | вход: **analyst / analyst** |
| `/` | список прогонов — должны быть два демонстрационных |
| `/configs` | конфигурация: датасет, входной формат, три процедуры, пять проверок |
| `/workspace` | рабочая область: написать проверку и выполнить её на прогоне |
| `/runs/<id>` | журнал этапов, переход «к коду», итоговые числа, ссылка на отчёт |
| `/runs/<id>/report` | единая таблица проверок + мнение ИИ + «Скачать HTML» |
| `/runs/<id>/explore` | сводная таблица с изменяемой раскладкой и переходом к заявке |

Демонстрационные прогоны уже в базе:

* **«Демонстрация: открытая часть (2002)»** — 2002 пары, **502** различия, **385** смен решения;
* **«Демонстрация: отложенные заявки (998)»** — 998 пар, **248** / **186**.

## 3. Девять шагов показа

Порядок совпадает со сценарием карточки задания. В колонке «ожидаемо» — числа, которые
должны быть на экране; если они другие, что-то не то (см. раздел 5).

| № | Что делаете | Ожидаемо | Время |
|---|---|---|---|
| 1 | «Конфигурации» → выбран датасет, видно предпроверку, три процедуры с переключателем «Файл .py / Рабочая область», поле «Входной формат» | «Пар заявок: 2002 (BEFORE 2002 / AFTER 2002)» | 40 с |
| 2 | Включить пять проверок → «Сохранить и запустить» | переход на страницу прогона | 10 с |
| 3 | Пока идёт расчёт — журнал этапов: Нормализация → Сравнение → Агрегация, прогресс, кнопки «К КОДУ» | три этапа, «обработано N из 2 002 пар» | 30–60 с |
| 4 | Нажать «К КОДУ» у нормализации | открывается `spr_normalize.py` — тот файл, который исполнялся | 10 с |
| 5 | Дождаться завершения | **502** различия, **385** смен решения, ссылка «Различия есть, решение не изменилось: 117» | — |
| 6 | «Сводная таблица»: строки `PATH`, колонки `CHANGE_TYPE` → «Пересчитать»; затем сменить раскладку | таблица перестраивается на сервере; мера — уникальные заявки | 60 с |
| 7 | Клик по числу в ячейке → список заявок → открыть заявку | число в ячейке = число заявок в списке; в карточке оба среза, продукты, атрибуты до/после, исходный JSON | 60 с |
| 8 | «Отчёт проверок»: таблица, вердикты HIGH/LOW, технические ошибки отдельным блоком, блок «Независимое мнение ИИ» | **32** строки; все пять выданных проверок | 60 с |
| 9 | «Скачать HTML» → открыть файл локально → клик по ссылке внутри | файл открывается без сети, ссылки ведут обратно в приложение | 40 с |

Дополнительно, если есть две минуты (это сильный момент):

* **новая проверка на глазах**: «Рабочая область» → «Новая проверка» → «Проверить контракт» →
  «Сохранить» → выбрать готовый прогон → «Выполнить на прогоне» → вернуться в отчёт: строка
  появилась, данные не пересчитывались;
* **второй пользователь**: войти как `analyst2` и открыть тот же прогон по прямой ссылке —
  «Этот прогон принадлежит другому пользователю».

Проверено на этой машине: весь маршрут занимает **96 секунд** машинного времени из 20 минут
(`tools/dev/rehearse_demo.py`), то есть времени на объяснения — с восьмикратным запасом.

### Как дать доступ коллеге из другой сети

```bash
./scripts/share.sh          # поднимает публичный туннель и печатает адрес
./scripts/share.sh --stop   # закрыть
```

Адрес вида `https://<случайное>.lhr.life` действует, пока живёт туннель: это бесплатный
туннель без аккаунта, постоянного имени у него нет. Ссылки в отчёте, скачанном через этот
адрес, ведут обратно на него же (приложение подставляет тот хост, по которому к нему
пришли), поэтому коллега не «выпадет» на внутренний адрес.

**Честно про ограничения бесплатных туннелей** (проверено на этой машине):

* исходящий канал этой машины фильтрует UDP, поэтому Cloudflare-туннель по QUIC не
  поднимается, а по HTTP/2 отдаёт 530;
* `localtunnel` работает, но показывает посетителю промежуточную страницу-предупреждение,
  из-за которой интерфейс не инициализируется, пока её не пройти;
* SSH-туннель `localhost.run` отдаёт страницу по одному запросу, но полноценная сессия
  с WebSocket через него не поднимается.

**Надёжный вариант для показа друзьям** — именованный туннель с вашим аккаунтом:

```bash
# Cloudflare, свой домен (бесплатный тариф)
cloudflared tunnel login
cloudflared tunnel create graeae
cloudflared tunnel route dns graeae graeae.example.com
cloudflared tunnel run --url http://localhost:8000 graeae
```

или `ngrok http 8000` с токеном из личного кабинета. В обоих случаях адрес постоянный и
WebSocket работает; наша сторона менять ничего не должна — приложение уже слушает
`0.0.0.0` и подставляет хост из запроса.

### Браузерная проверка (для приёмки)

```bash
# против работающего приложения (нужен хотя бы один завершённый прогон)
.venv/bin/python tools/dev/playwright/ui_walkthrough.py     # 13 проверок пути демонстрации

# или на изолированном стенде: своя база, свой порт, без мусора в демо-данных
.venv/bin/python tools/dev/playwright/run_isolated.py
```

Первый скрипт проходит путь жюри и обновляет скриншоты в `docs/screens/`.
Второй поднимает отдельную базу `change_analysis_ui`, приложение и воркер на порту 8091,
прогоняет проверки и всё убирает за собой.

## 4. Проверка «всё ли на месте» перед показом

```bash
cd <корень репозитория>          # там, куда склонирован репозиторий
./scripts/verify.sh
```

Три шага: модульные тесты → сверка с эталоном организаторов → сверка чисел в документации
с базой. Ожидаемый хвост вывода:

```
=== OPEN ===
apps                         2002   expected 2002
comparison rows            289533   expected 289533
apps with any difference      502   expected 502
apps with decision flip       385   expected 385
--- segment layer vs expected_*.csv ---
ALL SEGMENT FIELDS MATCH
```

Полный набор тестов (медленнее, нужна отдельная база): `./scripts/verify.sh --full` —
**310 тестов**.

### Пользователи и доступ коллегам

В базе пять учётных записей; у каждого пользователя свои прогоны, конфигурации и
рабочая область:

| Логин | Пароль | Для чего |
|---|---|---|
| `analyst` | `analyst` | основной демонстрационный (два готовых прогона) |
| `analyst2` | `analyst2` | показ изоляции: чужие прогоны закрыты |
| `amir` | `amir` | личный аккаунт |
| `daniil` | `daniil` | личный аккаунт |
| `guest` | `guest` | «зайти и посмотреть»: свой готовый прогон 2002 пары, 502 / 385 |

Добавить ещё:

```bash
.venv/bin/python -m change_analysis.cli useradd <логин> [пароль] --name "ФИО"
.venv/bin/python -m change_analysis.cli users        # список
.venv/bin/python -m change_analysis.cli run <логин>  # сразу сделать ему прогон
```

**Пароли по умолчанию — учебные.** Если сайт выходит в интернет, поменяйте их
(`set_password` в `change_analysis.auth.service`) или создайте новых пользователей с
нормальными паролями: система многопользовательская, но не «боевая» — защиты от
перебора и ограничения частоты запросов в ней нет.

### Если туннель поднялся, но сайт «пустой»

Симптом: адрес открывается, но интерфейс не появляется. Причина — канал не пропускает
файлы интерфейса или WebSocket. Проверка одной командой:

```bash
./scripts/publish.sh --check https://<адрес>
```

Скрипт скачивает реальный ресурс интерфейса (47 КБ) и говорит прямо: канал годится или
нет. **Измеренная картина на этом подключении** (Москва, 5.228.117.18, прокси выключен):

| Способ | Что происходит |
|---|---|
| Cloudflare Tunnel (быстрый и именованный) | соединение регистрируется, запросы → **502/530**, сессия умирает через ~6 с |
| serveo / pinggy / localhost.run (SSH) | HTML приходит (12 406 байт), файлы интерфейса обрываются на ~12 КБ → пустая страница |
| bore.pub (TCP 7835) | не отвечает |
| **прямой HTTPS с этой же машины** | 20 МБ за 5.6 с, отправка 1 МБ за 0.6 с |

Отсюда вывод: фильтруются нестандартные порты (7844 у cloudflared, 7835 у bore) и
длительные туннельные сессии. Приложение и полоса ни при чём — прямой обмен идёт на
3.5 МБ/с.

**Что работает:**

1. **Локальная сеть** — `http://192.168.0.27:8000`, любые устройства в той же сети.
2. **Мобильная точка доступа** — раздать интернет с телефона, запустить
   `./scripts/publish.sh`: туннель и домен `noway.qzz.io` уже настроены в аккаунте
   Cloudflare, на чистой сети порт 7844 не фильтруется.
3. **VPS** — единственный вариант, где сайт живёт круглосуточно и не зависит от
   ноутбука. Разворачивание — по `README.md` §7.

### Почему публичный доступ не поднимается с этой сети (измерено)

| Факт | Значение |
|---|---|
| Внешний IP, который видит интернет | `5.228.117.18` |
| Внешний IP, который видит **роутер** | `10.80.152.235` — приватный адрес |
| Что это значит | мы за **двойным NAT (CGNAT)**: входящие соединения до нас не доходят |
| UPnP на роутере | работает, порт 8000 проброшен на `192.168.0.27` (`scripts/open_port.py`) |
| Проверка снаружи | `http://5.228.117.18:8000/login` — таймаут из внешней сети |
| IPv6 | адрес есть (`2a02:2168:…`), но шлюз не отвечает — выхода нет |
| Cloudflare Tunnel | коннекторы регистрируются, но статус туннеля **degraded**, запросы → **502** (проверено: два туннеля, два имени, TCP/IPv4, регион US, версия 2026.10.7) |
| SSH-туннели (serveo, pinggy, localhost.run) | HTML 12 КБ проходит, файлы интерфейса обрываются |
| Прямой HTTPS с этой же машины | 20 МБ за 5.6 с — полоса и MTU в порядке |

Вывод: дело не в приложении и не в скриптах — **провайдер не даёт входящий трафик**.
Туннель Cloudflare теоретически обходит CGNAT, но конкретно это подключение рвёт его
служебные сессии (туннель числится `degraded`).

**Что разблокирует публичный доступ:**

1. **Публичный IP от провайдера** (обычно заявление в поддержку; часто 0–200 ₽/мес).
   После этого достаточно `./scripts/open_port.py` — сайт откроется по
   `http://<внешний IP>:8000` без всяких туннелей.
2. **VPS** (3–5 €/мес) — единственный вариант, где сайт живёт без ноутбука; разворачивание
   по `README.md` §7, перенос данных — `.venv/bin/python -m change_analysis.cli bootstrap`
   плюс копия папки данных.
3. Пока ни того, ни другого нет — работает **локальная сеть**: `http://192.168.0.27:8000`.

## 5. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| Страница не открывается | `./scripts/demo.sh` ещё раз: он покажет, что не поднялось, и укажет лог в `/tmp/spr-demo/` |
| Прогон висит в «в очереди» | не запущен worker: `./scripts/demo.sh` поднимет его; проверить `pgrep -af worker.main` |
| В отчёте нет строк проверок | при запуске не были включены проверки — в «Конфигурациях» включить пять переключателей и запустить снова |
| Сводная открывается секундами вместо долей секунды | таблицы «распухли» после удаления прогонов: `psql … -c "VACUUM (ANALYZE) ca.pivot_membership;"` (на этой машине это давало ×8) |
| Страница показывает старое поведение | перезапустить `./scripts/demo.sh --stop` и заново |
| Блок ИИ пишет «не настроено» | нет сети или ключа; числа и вердикты от него не зависят — так и сказать |
| Ссылки в скачанном HTML не открываются | приложение было запущено в другой сети: перезапустить, адрес определится заново |

## 6. Чего не обещать

Говорить честно, если спросят:

* **GPU не измерен** — RAPIDS не собирается под Python 3.14, на машине 4 ГБ VRAM; все числа — CPU;
* **инкрементальной загрузки нет** — отчёт публикуется после полного прогона (пункт задания помечен «не обязательно»);
* **установка проверялась на этой машине** (пустое окружение и пустая база), но не на второй;
* **масштаб 20 000 заявок не запускался**;
* **мнение ИИ** — вспомогательный блок: он не меняет ни одного числа и без ключа честно об этом пишет.

Все эти ограничения зафиксированы в [`STATUS.md`](STATUS.md), а результаты состязательных
проверок — в [`AUDIT.md`](AUDIT.md).
