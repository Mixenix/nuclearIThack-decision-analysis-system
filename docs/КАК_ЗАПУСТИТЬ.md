# Как запустить и что показывать

Короткая инструкция на 1 страницу: три команды до работающего приложения, затем
9 шагов демонстрации с ожидаемыми числами. Подробный 20-минутный сценарий с репликами —
в [`DEMO.md`](DEMO.md); здесь только то, что нужно в момент показа.

---

## 1. Запуск (60 секунд)

```bash
cd /home/mixantax/nuclearIThackWorkingDir/app
./scripts/demo.sh
```

Скрипт поднимает PostgreSQL, применяет миграции, создаёт демо-пользователей и датасет,
запускает веб-приложение и отдельный worker, затем печатает адрес. Например:

```
Готово. Открывайте:
  http://192.168.0.27:8000
  вход: analyst / analyst   (второй пользователь: analyst2 / analyst2)
```

Адрес определяется автоматически: при смене сети (дом, вуз, площадка) он подстроится сам,
переписывать конфигурацию не нужно. Остановить всё — `./scripts/demo.sh --stop`.

Если приложение уже запущено вручную (`./scripts/web.sh` и `./scripts/worker.sh`), скрипт
ничего не сломает: он переиспользует работающие процессы.

**Важно:** после любой правки кода приложение нужно перезапустить — autoreload выключен,
иначе страница продолжит отдавать старый код из памяти.

## 2. Что открыть

| Адрес | Что там |
|---|---|
| `/login` | вход: **analyst / analyst** |
| `/` | список прогонов — должны быть два демонстрационных |
| `/configs` | конфигурация: датасет, входной формат, три процедуры, пять проверок |
| `/workspace` | рабочая область: написать проверку и выполнить её на прогоне |
| `/runs/<id>` | журнал этапов, переход «к коду», итоговые числа, ссылка на отчёт |
| `/runs/<id>/report` | единая таблица проверок + мнение ИИ + «Скачать HTML» |
| `/runs/<id>/explore` | сводная таблица с изменяемой раскладкой и переходом к заявке |

Демонстрационные прогоны уже в базе:

* **«Демонстрация: открытая часть (2002)»** — 2002 пары, **502** различия, **385** смен решения;
* **«Демонстрация: отложенные заявки (998)»** — 998 пар, **248** / **186**.

## 3. Девять шагов показа

Порядок совпадает со сценарием карточки задания. В колонке «ожидаемо» — числа, которые
должны быть на экране; если они другие, что-то не то (см. раздел 5).

| № | Что делаете | Ожидаемо | Время |
|---|---|---|---|
| 1 | «Конфигурации» → выбран датасет, видно предпроверку, три процедуры с переключателем «Файл .py / Рабочая область», поле «Входной формат» | «Пар заявок: 2002 (BEFORE 2002 / AFTER 2002)» | 40 с |
| 2 | Включить пять проверок → «Сохранить и запустить» | переход на страницу прогона | 10 с |
| 3 | Пока идёт расчёт — журнал этапов: Нормализация → Сравнение → Агрегация, прогресс, кнопки «К КОДУ» | три этапа, «обработано N из 2 002 пар» | 30–60 с |
| 4 | Нажать «К КОДУ» у нормализации | открывается `spr_normalize.py` — тот файл, который исполнялся | 10 с |
| 5 | Дождаться завершения | **502** различия, **385** смен решения, ссылка «Различия есть, решение не изменилось: 117» | — |
| 6 | «Сводная таблица»: строки `PATH`, колонки `CHANGE_TYPE` → «Пересчитать»; затем сменить раскладку | таблица перестраивается на сервере; мера — уникальные заявки | 60 с |
| 7 | Клик по числу в ячейке → список заявок → открыть заявку | число в ячейке = число заявок в списке; в карточке оба среза, продукты, атрибуты до/после, исходный JSON | 60 с |
| 8 | «Отчёт проверок»: таблица, вердикты HIGH/LOW, технические ошибки отдельным блоком, блок «Независимое мнение ИИ» | **32** строки; все пять выданных проверок | 60 с |
| 9 | «Скачать HTML» → открыть файл локально → клик по ссылке внутри | файл открывается без сети, ссылки ведут обратно в приложение | 40 с |

Дополнительно, если есть две минуты (это сильный момент):

* **новая проверка на глазах**: «Рабочая область» → «Новая проверка» → «Проверить контракт» →
  «Сохранить» → выбрать готовый прогон → «Выполнить на прогоне» → вернуться в отчёт: строка
  появилась, данные не пересчитывались;
* **второй пользователь**: войти как `analyst2` и открыть тот же прогон по прямой ссылке —
  «Этот прогон принадлежит другому пользователю».

Проверено на этой машине: весь маршрут занимает **96 секунд** машинного времени из 20 минут
(`tools/dev/rehearse_demo.py`), то есть времени на объяснения — с восьмикратным запасом.

## 4. Проверка «всё ли на месте» перед показом

```bash
cd /home/mixantax/nuclearIThackWorkingDir/app
./scripts/verify.sh
```

Три шага: модульные тесты → сверка с эталоном организаторов → сверка чисел в документации
с базой. Ожидаемый хвост вывода:

Полный набор тестов (медленнее, нужна отдельная база): `./scripts/verify.sh --full` —

## 5. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| Страница не открывается | `./scripts/demo.sh` ещё раз: он покажет, что не поднялось, и укажет лог в `/tmp/spr-demo/` |
| Прогон висит в «в очереди» | не запущен worker: `./scripts/demo.sh` поднимет его; проверить `pgrep -af worker.main` |
| В отчёте нет строк проверок | при запуске не были включены проверки — в «Конфигурациях» включить пять переключателей и запустить снова |
| Сводная открывается секундами вместо долей секунды | таблицы «распухли» после удаления прогонов: `psql … -c "VACUUM (ANALYZE) ca.pivot_membership;"` (на этой машине это давало ×8) |
| Страница показывает старое поведение | перезапустить `./scripts/demo.sh --stop` и заново |
| Блок ИИ пишет «не настроено» | нет сети или ключа; числа и вердикты от него не зависят — так и сказать |
| Ссылки в скачанном HTML не открываются | приложение было запущено в другой сети: перезапустить, адрес определится заново |

## 6. Чего не обещать

Говорить честно, если спросят:

* **GPU не измерен** — RAPIDS не собирается под Python 3.14, на машине 4 ГБ VRAM; все числа — CPU;
* **инкрементальной загрузки нет** — отчёт публикуется после полного прогона (пункт задания помечен «не обязательно»);
* **установка проверялась на этой машине** (пустое окружение и пустая база), но не на второй;
* **масштаб 20 000 заявок не запускался**;
* **мнение ИИ** — вспомогательный блок: он не меняет ни одного числа и без ключа честно об этом пишет.

Все эти ограничения зафиксированы в [`STATUS.md`](STATUS.md), а результаты состязательных
проверок — в [`AUDIT.md`](AUDIT.md).
